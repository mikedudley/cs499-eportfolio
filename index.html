01 / INTRODUCTION

Professional self-assessment

THE BIG PICTURE

My computer science coursework has strengthened my ability to approach software development as a process of analysis, design, implementation, testing, and continuous improvement.

Building this capstone ePortfolio provided an opportunity to revisit an earlier Android application and evaluate it with the perspective gained throughout the program. Instead of simply adding features, I focused on making the application easier to maintain, more useful to its users, and more deliberate about data integrity and security.

My work with Java, Android, and SQLite has reinforced the relationship between application design and the underlying data model. Separately, full-stack web application coursework introduced me to broader architectural considerations, including how interfaces, application logic, and data services work together.

The three enhancements featured here represent complementary skills: improving software structure and validation, using algorithms to turn raw records into meaningful progress information, and designing a relational database that supports individual user accounts. Together, they illustrate an iterative approach to solving computing problems and evaluating design trade-offs.

Code review and technical writing have also helped me practice communicating decisions to audiences who may have different levels of technical knowledge. As I continue developing professionally, I want to build reliable software, collaborate effectively, and remain attentive to the security and usability of the systems I create.

ENHANCEMENT 01

Software Design and Engineering

The original Weight Tracker provided basic functionality for recording and managing weight information. The software engineering enhancement focused on improving input validation, handling invalid values more clearly, and reorganizing portions of the application to make the code easier to understand and maintain. An editable goal-weight field also improved usability by replacing a fixed value with user input.

These changes demonstrate the importance of designing for both users and future developers. Input validation reduces preventable errors, while clearer separation of responsibilities makes later enhancements easier to implement. This work established a more reliable foundation for the subsequent algorithmic and database improvements.

ENHANCEMENT 02

Algorithms and Data Structures

The second enhancement introduced a WeightEntry model and used a collection of entries to support chronological sorting and progress calculations. A dedicated WeightAnalyzer class calculates overall weight change, a recent moving average, the latest trend, and distance from a goal weight. Java's LocalDate API improved the handling of dates compared with treating them as ordinary strings.

By separating analytical logic from the activity interface, the application became easier to reason about and more useful to its users. The work also highlighted design trade-offs around data representation, ordering, and compatibility with older Android versions.

ENHANCEMENT 03

Databases

The final enhancement redesigned the SQLite data model so that weight entries belong to individual user accounts. User-specific queries restrict the retrieval and modification of records, and goal weights are stored persistently. The schema also incorporates foreign keys, constraints, and an index to strengthen data relationships and retrieval.

Authentication was changed to avoid storing passwords directly as plaintext. The implementation uses SHA-256 hashing, which is an improvement over plaintext storage but is not sufficient for production password security; a salted password-specific key-derivation function would be a more appropriate future improvement. This enhancement emphasized how data modeling and security decisions affect application behavior.
