ENHANCEMENT 01

Software Design and Engineering

Artifact Description and Justification

The artifact I selected is an Android Weight Tracker application that I originally created as part of my Computer Science coursework. The application was developed using Java and XML in Android Studio and allows users to create an account, log in, record and manage weight entries, and use SMS notification functionality. I selected this artifact because it demonstrates several software development skills, including user-interface design, object-oriented programming, input handling, database interaction, and Android development.

My code review showed that although the original application was functional, its design could be improved. For this enhancement, I focused on making the code more maintainable and reliable. I separated validation and goal-weight logic from the main activity, improved input validation and error handling, removed the hard-coded 180-pound goal by allowing the user to enter a goal weight, and improved documentation. These changes demonstrate my ability to refactor an existing application using professional software engineering practices.

Course Outcomes

This enhancement primarily supports the fourth course outcome because I applied software engineering techniques such as separation of concerns, modularity, validation, and error handling to improve an existing computing solution. It also supports the fifth outcome by incorporating defensive programming and considering how invalid input and other potential problems should be handled. The enhancement also contributes to the communication outcome through clearer code organization and documentation. The subsequent algorithms and data structures and database enhancements further demonstrate these outcomes through data analysis, relational database design, and improved security practices.

Reflection

The most important lesson I learned from this enhancement was that improving software does not always require adding more features. The original application worked, but separating business logic from the user interface made the code easier to understand, maintain, and test. I also learned the importance of validating input instead of silently ignoring errors.

One challenge was determining which improvements belonged in this milestone. My code review identified issues involving software design, algorithms, databases, and security. I chose to focus this enhancement on software engineering improvements while saving weight-history analysis and data structures for my algorithms enhancement and larger schema and security changes for my database enhancement. This helped me better understand how thoughtful refactoring can turn functional code into a more professional and maintainable application.

ENHANCEMENT 02

Algorithms and Data Structures

Artifact Description and Justification

The artifact I selected is an Android Weight Tracker application that I originally created during my Computer Science coursework. The application was developed in Java and XML using Android Studio and allows users to record, update, delete, and view their weight history. I selected this artifact because the original application stored and displayed weight records but performed very little analysis on the data, which provided an opportunity to demonstrate my skills with algorithms and data structures.

For this enhancement, I created a WeightEntry model and used an ArrayList<WeightEntry> to represent the user's weight history after retrieving records from the SQLite database. I also changed the application to use LocalDate for processing dates rather than treating dates only as strings. I developed a WeightAnalyzer class containing algorithms for chronological sorting, total weight change, a three-entry moving average, recent weight trend, and distance from the user's goal weight. The application now displays these calculations in a Progress Summary and automatically sorts entries chronologically even when they are entered out of order.

Course Outcomes

This enhancement most directly supports the third course outcome by demonstrating my ability to design and evaluate a computing solution using algorithmic principles and appropriate data structures. I selected an ArrayList because the application benefits from sequential traversal and indexed access to recent weight entries. The enhancement also supports the fourth outcome because I used Java collections, LocalDate, comparators, and modular classes to create functionality that provides meaningful information from stored data. It also contributes to the communication outcome because the Progress Summary presents the results of the algorithms in a clear format for the user.

Reflection

Through this enhancement, I learned that selecting an appropriate data structure can make both data processing and future development easier. Instead of reading each database record and immediately displaying it, the application now converts the records into WeightEntry objects, stores them in a collection, sorts the collection, analyzes it, and then presents the results. This separation made the application's data flow easier to understand and test.

One challenge was handling dates correctly. The original application treated dates as strings, which was not ideal for chronological comparisons. I changed the model to use LocalDate and implemented flexible parsing so users can enter dates such as 9/1/26 while the application can still perform reliable chronological sorting. Overall, this enhancement helped me better understand how algorithms and data structures can transform stored data into useful information rather than simply displaying it.

ENHANCEMENT 03

Databases

Artifact Description and Justification

The artifact I selected is an Android Weight Tracker application that I originally created during my Computer Science coursework. The application was developed using Java, XML, and SQLite and allows users to create an account, log in, set a goal weight, and manage their weight history. I selected this artifact because its original database implementation provided basic data storage but had opportunities to improve its structure, security, and management of user-specific information.

For this enhancement, I redesigned portions of the SQLite database to create a relationship between users and their weight entries. Each weight record is now associated with a specific user through a user ID, creating a one-to-many relationship between the users and weight entries. Database queries were also updated so users can only retrieve, update, and delete their own records. I added database persistence for each user's goal weight, allowing the value to remain available after the application is closed. I also improved the database schema by using constraints, foreign keys, an index, and appropriate data types. Finally, I improved authentication security by replacing plaintext password storage with hashed passwords.

Course Outcomes

This enhancement most directly supports the fourth course outcome because I used database design and development techniques to create a more useful and reliable application. The improved relational structure, user-specific queries, database constraints, and persistent goal data demonstrate my ability to use computing tools and practices to solve application requirements. The enhancement also demonstrates progress toward the fifth course outcome by addressing security concerns in the original application. Parameterized queries and ownership checks help protect user data, while password hashing prevents passwords from being stored directly as plaintext. While SHA-256 hashing is an improvement over plaintext storage, a production application would use a salted password hashing algorithm specifically designed for password storage.

Reflection

This enhancement helped me better understand that database development involves more than simply storing and retrieving information. The structure of the database directly affects data integrity, security, and how easily an application can manage information. Creating a relationship between users and weight records made the application behave more realistically because each account now maintains its own weight history and goal.

One challenge was modifying the database without breaking the functionality added during my previous enhancements. Changes to the database methods also required changes to the login and weight-tracking code so the user's ID could be passed through the application and included in database operations. Testing multiple accounts helped verify that records remained separated correctly. Overall, this enhancement improved my understanding of relational database design, persistent application data, secure data handling, and the importance of considering database structure as part of the overall application architecture.
